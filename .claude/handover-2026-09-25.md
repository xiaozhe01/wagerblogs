## 2. What the 29 commits did

### Phase 4F — the crawler and navigation surfaces (`7869d6a` … `c7dc2fd`)

Four surfaces each built their own URLs from their own fixtures and had drifted
from the routes. All now read Payload.

| Sub-phase | Surface                 | Defect found                                                     |
| --------- | ----------------------- | ---------------------------------------------------------------- |
| 4F-0      | `lib/nav.ts`            | Reviews dropdown emitted `/reviews/casinos`, a 404 on every page |
| 4F-1      | `app/sitemap.ts`        | six dead entries, eight live routes missing                      |
| 4F-2      | `app/llms.txt/route.ts` | five dead links, no authors, no news stories                     |
| 4F-3      | `lib/search.ts`         | a dead URL returned as a live search hit                         |
| 4F-4      | fixture cleanup         | see below                                                        |

`lib/urls.ts` is now the single URL derivation shared by all three crawler
surfaces — each previously built its own paths, which is precisely how they
drifted apart.

**Search costs zero queries per request.** The corpus is built behind
`unstable_cache` (1h TTL) and dropped on write by an `afterChange` hook on each
searchable collection. A cache miss issues six concurrent queries; a user's
search issues none. Corpus grew 46 → 53 documents.

**4F-4 acted on a distinction worth keeping:** `lib/categories.ts` was deleted
(genuinely orphaned), but `lib/blog.ts`, `news.ts`, `reviews.ts` and `faq.ts`
were **moved to `scripts/fixtures/`**, not deleted — they are the input the seed
scripts read. Deleting them would have broken the ability to rebuild the
database. `lib/` now holds no fixture files.

### The security fix that interrupted Phase 5 (`dc38e2d`, `c2139b3`)

Found while verifying preview: **every collection shipped `read: () => true`**.
Payload does not filter `_status` or a moderation field on its own, so
`/api/<slug>` served drafts and unmoderated content to anonymous callers — two
draft reviews, one of them an unreleased review of the primary domain, and one
draft author.

`publishedFilter` was never a security boundary: it guards at the query layer,
one hand-written call at a time, and cannot guard a request that never reaches
those routes. Ten collections now carry access rules, **one per visibility
model** — the schema does not share a vocabulary:

```
readPublished       Reviews, Articles, News, Authors   _status = published
readPublicComments  Comments                           status in (approved, edited)
readApproved        ReaderReviews                      status = approved
readOpenThreads     ForumThreads                       status in (open, locked)
readUnflagged       ForumReplies                       not flagged
readEditorsOnly     site-users, Notifications          no anonymous read
```

Editor identity keys off `req.user.collection === "users"`. It **fails closed**:
an unrecognised session falls through to the anonymous filter.

### The two bugs that fix caused (`b0aa561`, `30ec0e7`)

1. **Draft-mode queries passed no user**, so the new access rules filtered
   drafts out at the data layer and preview showed published content. Fixed by
   resolving the editor through `payload.auth` and carrying it into
   `payload.find`. `overrideAccess: false` stands; the rules were not weakened.

2. **Six call sites destructured `{ where, draft }` and silently dropped
   `user`** — so index routes worked and every detail route 404'd in preview.
   All call sites now spread. `tests/draft-auth-propagation.test.ts` guards it,
   and the guard was verified to fail when the bug is reintroduced.

**This diverges from Payload's canonical example deliberately.** Their website
template uses `overrideAccess: draft`, which works because their collections
ship `read: () => true`. Ours would bypass the rules we just added. Theirs fails
open; ours fails closed. Do not "fix" this by matching the template.

### Hardening and polish (`3e192ac`, `042c8ea`, `54e786d`, `e6fe8df`, `6a5feff`, `32d9037`)

- **Open redirect closed.** `/\evil.com` and `/..//evil.com` both escaped to an
  external origin after browser normalisation. `lib/safe-path.ts` parses against
  a sentinel base and rejects post-normalisation `//`.
- `findByID` **throws** on a missing record — the preview URL builder caught it
  rather than erroring the admin's Preview button.
- `resolvePreviewUser` wrapped in React `cache()`; three routes were
  authenticating twice per request.
- **LCP fix**: the real LCP was a card thumbnail, not the article hero. The
  first card has no image, so the candidate is the first card that _has_ one.
- **Pagination gap**: `PAGE_SIZE = 3` fed two-column grids, leaving an empty
  cell on every page of `/articles` and `/reviews/[vertical]`. `GRID_PAGE_SIZE = 4`.

## 3. The admin white-label

Landed 2026-09-26 as five commits, one per concern: grouping `fe29636`, theme
`8d82871`, branding `aceeca6`, i18n `d91951f`, dashboard `5bb4097`. Green
throughout (build, tsc, eslint, 60 unit tests, 254 a11y).

**The concerns have a required order.** The dashboard panels import
`collectionLabel` from `collections/i18n-labels.ts`, so i18n must land first;
and that dictionary keys off the _new_ group names, so the regrouping must land
before it. Branding · theme · grouping · dashboard · i18n — the order this
document originally suggested — does not build.

### New files

```
app/(payload)/custom.css              admin theme + interaction overrides
app/(payload)/next/editing-now/       polling endpoint for the lock panel
collections/i18n-labels.ts            groups, collection names, field labels (zh)
components/admin/                     Logo, Icon, Dashboard, 5 panels, ui, strings
lib/editing-now.ts                    lock gathering, shared by render and endpoint
tests/admin-labels.test.ts            field-tree invariant guard
```

### What it does

**Branding.** Payload's logo and `- Payload` title suffix are gone; the login
screen carries a WagerBlogs wordmark. `theme: "light"` — the site declares no
dark mode.

**Theme.** Payload resolves every `--theme-elevation-*` from one
`--color-base-*` ramp, so overriding that ramp repaints the panel without
touching a component. The ramp is **luminance-matched**: each step holds the
OKLab lightness of the grey it replaces and moves only hue, measured within
0.5% at every step. An earlier attempt anchored on our own token values and
collapsed contrast — that failure is recorded in the file's comment.

**Interaction.** Nothing underlines; the row tints. Applied to the nav, the
dashboard and every collection list. The list table's record links are a Next
`<Link>` with no stable class, so the underline was the browser default —
`.table a` is the durable selector, not `.default-cell__first-cell`.

**Grouping.** Nine sidebar groups with six singletons became six groups with
none. Group order follows the `collections` array order.

**Dashboard.** `admin.components.views.dashboard` fully replaces Payload's
default view. Five panels, all reading live data — none contain fixtures:

| Panel                | Notes                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| Awaiting publication | draft queue across the four editorial collections                                                  |
| Recently edited      | last 10 edits, with Draft/Placeholder chips                                                        |
| By collection        | live/draft/placeholder per collection, as a real `<table>` so header and body share column widths  |
| Awaiting moderation  | all four UGC queues, each with its own vocabulary                                                  |
| Coverage by vertical | flags Esports Betting: `hasReviews: true`, zero reviews — a live, empty `/reviews/esports-betting` |
| Editing now          | reads `payload_locked_documents`, polls every 10s                                                  |

`Editing now` polls a dedicated endpoint rather than `router.refresh()`,
because one dashboard render issues **~46 queries**. It pauses when the tab is
hidden. Payload exposes no event stream for locks — its own lock UI polls too.

**i18n.** Admin chrome in English or Chinese Simplified, selected by browser
locale and overridable per account. Two dictionaries, both with **English
fallback**, so a new collection is never blocked on translation:

- `collections/i18n-labels.ts` — group names, collection names, ~70 field labels.
  Applied centrally via `localise()` in `payload.config.ts`; **no collection
  file was edited.**
- `components/admin/strings.ts` — all dashboard copy, relative times, date locale.

`tests/admin-labels.test.ts` asserts `localise` never alters the field tree's
shape, and verifies the guard fails when a field is dropped or renamed. It also
caught that `AdminUsers` has `fields: []` by design.

## 5. Parked, with reasons

In CONTENT-BACKLOG.md:

- **Editor attribution / activity log** — parked on cost. Nothing records who
  edited a document: no `updatedBy`, no user column on `_<collection>_v`, no role
  field on `users`. Storage is cheap (~250–400 B/row, ~65 MB/year at 500
  mutations/day); the objection is permanent write amplification for a team where
  "who changed this" is answerable by asking. If picked up: roles first, then a
  log whose title is **denormalised** (a deleted document cannot be dereferenced,
  which is exactly when the log matters).
- **IAM-style roles** — researched, not built. Payload's access surface is
  `create/read/update/delete/readVersions/unlock` per collection returning
  `boolean | Where`, plus `admin` (boolean) and field-level `create/read/update`
  (boolean). `AccessResult = boolean | Where` is row-level security, which IAM
  cannot express. Rules are **code, not data** — a data-driven matrix is
  buildable but you build the engine. **`auth.depth` defaults to 0**, so the
  user's group must be populated at auth time or every check costs a query.
  Decide first: lockout escape hatch, matrix shape, and whether row-level scoping
  ("own articles only") is needed.
- **Cache invalidation scope** — search busts on write; sitemap, llms.txt and
  prerendered pages carry a 1h TTL with no per-tag invalidation. A deleted record
  keeps returning 200 for up to an hour.
- **Seed idempotency** — both seeds key "already exists" on slug or name, so a
  record renamed in the admin is re-created on the next run. Do not run a seed
  against a hand-edited database.

## 6. Things that will bite the next person

- **Payload config changes need a dev restart**, not hot reload. A stale server
  once made a correct fix look broken for several minutes.
- **`payload.find` with `overrideAccess: false` and no `user` sees only
  published.** Always spread `publishedFilter`, never destructure it.
- **The two "Phase 5"s.** `docs/04`'s Phase 5 is Clerk auth; FW-1's is Live
  Preview. CLAUDE.md now names the live track.
- **The admin dashboard is auth-gated**, so it cannot be screenshotted without a
  session. Every iteration on it needs a human to look.
